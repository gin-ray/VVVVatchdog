# Техническое Задание: VVVVatchdog

## 1. Обзор проекта
**VVVVatchdog** — система мониторинга (Watchdog) для мультимедийных инсталляций. 
**Цель**: Обеспечить бесперебойную работу приложений, автоматический перезапуск при зависаниях, сбор метрик и нотификации.
**Текущий этап**: Рефакторинг прототипа в модульную архитектуру MVVM.

## 2. Функциональные требования

### 2.1. Мониторинг процессов
- Отслеживание состояния списка процессов (по имени/ID).
- Определение зависших процессов (Not Responding).
- Проверка потребления ресурсов (CPU/RAM) - *Опционально на первом этапе*.

### 2.2. Управление (Watchdog Logic)
- Автоматический перезапуск процесса при падении или зависании.
- Настраиваемые таймауты (время ожидания перед перезапуском).
- "Graceful" завершение процессов перед убийством.
- Ограничение количества перезапусков за период времени (защита от boot loop).

### 2.3. Пользовательский интерфейс (UI)
- Реализация на **VL.ImGUI**.
- Dashboard со списком отслеживаемых приложений и их статусами (Running, Frozen, Stopped, Restarting).
- Лог событий (консоль).
- Системный трей (свернуть/развернуть).
- Редактор настроек.

### 2.4. Конфигурация
- Хранение настроек в XML (сериализация).
- Настройки для каждого приложения: Путь, Аргументы запуска, Таймауты.

### 2.5. Коммуникация
- OSC API для внешнего управления и статусов.

## 3. Архитектура и Структура данных (Model)

### 3.1. Data Models (C# Records)
**AppConfig**
- `Name` (Monitor Name)
- `FilePath` (Path to executable)
- `Arguments` (Startup args)
- `WatchdogEnabled` (bool)
- `TimeoutSec` (float)

**AppState**
- `IsRunning` (bool)
- `IsResponding` (bool)
- `Pid` (int)
- `Uptime` (TimeSpan)
- `RestartCount` (int)
- `LastEvent` (String/Enum)

**WatchdogModel** (Root)
- `Apps` (Spread<AppConfig>)
- `GlobalSettings` (GlobalConfig)

**GlobalConfig**
- `MaxRestartsPerHour` (int) - Максимальное количество перезапусков в час (защита от boot loop)
- `CheckIntervalMs` (int) - Интервал проверки процессов в миллисекундах
- `GracefulShutdownTimeoutSec` (float) - Таймаут для graceful завершения процесса
- `OSCPort` (int) - Порт для OSC коммуникации
- `ConfigFilePath` (string) - Путь к файлу конфигурации XML

**ProcessStatus** (Enum)
- `Stopped` - Процесс не запущен
- `Running` - Процесс работает нормально
- `Frozen` - Процесс завис (Not Responding)
- `Restarting` - Процесс перезапускается
- `Error` - Ошибка при запуске/мониторинге

### 3.2. Архитектура папок
```text
VVVVatchdog/
├── src/
│   ├── Model/          # Определения Records (AppConfig, AppState) и логика данных

```

## 4. Последовательность реализации модулей

### Этап 1: Модель данных (Model)
1. Определить C# Records: `AppConfig`, `AppState`, `WatchdogModel`, `GlobalConfig`
2. Создать Enum `ProcessStatus`
3. Реализовать базовую валидацию данных

### Этап 2: Утилиты (Utils)
1. **XMLSerializer**: Сериализация/десериализация конфигурации в XML
2. **ProcessHelper**: 
   - Получение списка процессов по имени
   - Проверка состояния процесса (IsResponding)
   - Запуск процесса с аргументами
   - Graceful завершение процесса
   - Принудительное завершение процесса
3. **OSCService**: 
   - Инициализация OSC сервера
   - Отправка статусов процессов
   - Приём команд управления

### Этап 3: ViewModel
1. **WatchdogViewModel**: 
   - Управление состоянием всех отслеживаемых приложений
   - Реактивные каналы для обновления UI
   - Логика перезапуска с учётом ограничений
   - Обработка событий от ProcessHelper
2. **AppViewModel**: Управление состоянием одного приложения

### Этап 4: View (UI на VL.ImGUI)
1. **MainWindow**: Главное окно приложения
2. **DashboardWidget**: Список приложений со статусами
3. **LogWidget**: Консоль логов событий
4. **SettingsEditor**: Редактор конфигурации
5. **SystemTray**: Интеграция с системным треем

### Этап 5: Интеграция и тестирование
1. Создание тестовых патчей в папке `tests/`
2. Проверка работы всех модулей вместе
3. Тестирование сценариев: зависание, падение, перезапуск

## 5. Стек технологий
- **Платформа**: VVVV Gamma
- **UI**: VL.ImGUI
- **Logic**: C# Records, Reactive Extensions (Observable/Channels), MVVM Pattern
- **IO**: VL.IO.OSC
- **Сериализация**: System.Xml.Serialization (для XML конфигурации)
- **Процессы**: System.Diagnostics.Process (для работы с процессами)

## 6. Важные ограничения и требования

### 6.1. Безопасность
- **Защита от boot loop**: Ограничение количества перезапусков за период времени
- **Graceful shutdown**: Попытка корректного завершения перед принудительным убийством
- **Валидация путей**: Проверка существования исполняемых файлов перед запуском

### 6.2. Производительность
- Асинхронная проверка процессов (не блокировать UI)
- Эффективное использование ресурсов при мониторинге множества процессов
- Минимальное потребление памяти

### 6.3. Надёжность
- Обработка ошибок при работе с процессами
- Логирование всех критических событий
- Восстановление после сбоев
